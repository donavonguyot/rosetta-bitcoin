# Security Policy

RosettaBitcoin is a Bitcoin testnet4 validation and research workspace. It is
not a production guarantee, wallet, custody system, or security product.

## Supported Versions

Until a release policy exists, only the current default branch is in scope for
security review. This supported versions policy should be revisited before the
first tagged release.

## Reporting A Vulnerability

After the public GitHub repository exists, report vulnerabilities through
GitHub private vulnerability reporting.

Do not open public issues for exploitable or disclosure-sensitive bugs,
including consensus validation bypasses, P2P denial-of-service paths, storage
corruption, unsafe artifact publication, or security-sensitive dependency
problems.

When reporting, include:

- affected port or shared component;
- commit or artifact version;
- reproduction steps;
- expected and observed behavior;
- any relevant fixture, proof artifact, log excerpt, or Project report.

Security reports are evaluated against RB-owned evidence. Another port,
Reference Core, btcg, old IL, or archive material may help explain a report, but
they do not clear or prove a RosettaBitcoin claim by themselves.
